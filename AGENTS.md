# Project architecture rules

- Auth initialization must settle on success, rejected session reads and timeouts, validate identities with the auth server, and ignore stale lookups after newer auth events; storage failures must not revoke other devices or bypass protected routes.

- APR-ERGO records reuse documentos with tipo APR-ERGO and sector+function IDs in draft_snapshot (one APR per chosen function; status rascunho until first save, then salvo); company, contract, sectors and functions are read from their existing registries, and no emission workflow is implied by draft creation.
- APR-ERGO AI uses the existing streamed generation service and server-side exact document/company/contract/sector reads; options, matrix and formulas live only in supabase/functions/_shared/aprErgoPlanilha.ts (copied from the Anexo 03 workbook); AI may only pick listed options, unambiguous AEP D/I marks take precedence, and Perfil/Classificação are always recomputed, never AI-written. Reference files use the existing private Base bucket under company/contract/document/apr-base, keeping modules isolated without duplicate registries.
- APR-ERGO sector summaries share field-level preview/confirmation merging with risk rows; administrative conduct is a fixed per-level table in aprErgoIa.ts, synchronized whenever classification is recalculated, with exclusive conduct for restricted levels, so matrix authority is shared by generation, editing and export.
- APR-ERGO generated rows retain exact function/sector IDs (funcao_ids for shared activities), deduplicate technical circumstances across functions without quantity caps, and keep registry names out of circumstance text; the PDF consumes current sheet state using vector tables with explicit continuation rows and proportional photos to preserve long content across pages.
- APR-ERGO deletion uses a shared confirmation modal, an exact document ID/type/company/contract filter and only that document's private Base prefix; storage cleanup failures are reported separately so sibling APRs and registries remain untouched.
- AET (VALE) records reuse documentos with tipo AET-VALE, one draft per selected function (IDs in draft_snapshot, status rascunho until saved), reusing existing company/contract/sector/function registries; AEP context is read-only via selecionarSetorAep filtered to Alto/Crítico (presented as Alto/Muito Alto) without copying or inventing data.
- AET VALE field definitions, risk identity selection and non-destructive merging live in _shared/aetValeIa.ts; both steps and 5W2H persist together, and its authenticated AI endpoint reuses the existing shared Responses service with NDJSON heartbeats and server-derived exact scope to protect source records and manual data.
- AET VALE exports render the current complete form state as vector tables with explicit text continuations and proportional photos; the final 5W2H step shares the existing persisted etapa2 payload to retain legacy actions.
- AET VALE photo analysis uses authenticated, exact-scope multimodal Responses and deterministic canvas overlays, never generative photo alteration; originals and reviewed annotations persist together in the existing snapshot, with source hash and document/function IDs, and replacement invalidates annotations.
- AET VALE contract-level monthly plans reuse documentos with type AET-VALE-PLANO and a cronograma snapshot; month keys stay stable across period edits, and AI reads only saved AET-VALE evaluations with exact registry identities. Existing per-function 5W2H payloads remain independent. Template exports reuse the existing private templates bucket, DOCX/HTML renderers and XML sanitizer.

- Psychosocial report screen, PDF, and Word exports must consume the same numerically sorted group payload so presentation formats cannot diverge.
- Psychosocial report terminology and frequency values must be normalized before persistence and shared by screen, PDF, Word, and AI context so legacy wording cannot reappear.
- AEP/AET generation contexts must be read-only, scoped by exact company and contract IDs, then narrowed by sector/GHE/function, so documents cannot mix tenants or overwrite source records.
- AEP decision extraction must use the shared pure aepAprofundamento helper in client context and AET generation; all supplied identity constraints must match before selection, so technical deepening cannot attach to a different group.
- AEP risk generation must retain every context-supported severity, target per-agent coverage without fabricating factors, and map internal matrix levels to Low/Medium/High only at presentation boundaries.- AI generation edge functions must stream NDJSON (pings + final result/error) via supabase/functions/_shared/aiStream.ts and be consumed with src/lib/aiEdgeStream.ts, because buffered multi-minute responses exceed the function idle timeout.
- Psychosocial report groups must be rebuilt from the current Setores/Funções registry filtered by the evaluation's exact company and contract, merging only editable texts from saved reports, so stale or cross-contract identification never reappears.
- Psychosocial groups must include registered functions without respondents, use existing function IDs before unique legacy-name matching, and leave unassessed groups without risk factors so absent answers never become fabricated results.
- AEP/AET AI output must follow supabase/functions/_shared/redacaoTecnica.ts (prompt rules + post-filter of source/gap phrases) so final documents never expose data origin, missing data, or artificial pending evaluations.
